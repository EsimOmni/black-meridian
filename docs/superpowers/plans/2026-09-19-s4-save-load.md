## 0. What changed before a line was written

Six findings from driving the oracle and reading the engine source. Three of them **overturn the
planning package**; one **decides the slice's architecture**; F-6 was found during Step 1 and would
have failed a correct port. None came from plan prose.

### F-1 — `UBMSaveGame` as specified CANNOT COMPILE. The codec goes in BMCore. `[MEASURED]`

`05_DATA_MODEL.md` §7 prescribes:

```cpp
UCLASS() class UBMSaveGame : public USaveGame {
    UPROPERTY() TArray<FBMDistrictState>  Districts;   // <-- cannot compile
```

`FBMDistrictState`, `FBMFactionState`, `FBMJob` are **plain C++ structs** — no `USTRUCT`, no
`UPROPERTY`. `BMCore.Build.cs` declares `PublicDependencyModuleNames = { "Core" }` and says in a
comment that *"the ABSENCE of Engine is the enforcement mechanism."* A `UPROPERTY` over a
non-reflected struct is a UHT error. Making them `USTRUCT` would pull CoreUObject into BMCore and
**breach the determinism wall** — the thing S0 built the module boundary to prevent.

**Verified escape hatch.** The whole `FArchive` family lives in **`Core`**, not CoreUObject:

| Header | Module | Verified |
|---|---|---|
| `Serialization/Archive.h` (incl. `CORE_API operator<<(FArchive&, FString&)`, Archive.h:1695) | Core | ✅ |
| `Serialization/MemoryWriter.h` / `MemoryReader.h` / `BufferArchive.h` | Core | ✅ |
| `Misc/FileHelper.h` | Core | ✅ (already used by `BMSimVectorTest.cpp`) |
| `Containers/Array.h:4348`, `Map.h.inl:1840`, `UnrealString.h.inl:1472` — `operator<<` | Core | ✅ |

**`CoreMinimal.h` already `#include`s `Serialization/Archive.h`** — so `FArchive` is in scope in
every BMCore header **today**, with no new include and **no `BMCore.Build.cs` change.** The audited
include graph of those four serialization headers reaches no CoreUObject header. (`UObject/NameTypes.h`
looks alarming and is a red herring: the `UObject/` *directory* exists inside the Core module.)

**Decision D-S4-1: `FBMSaveCodec` is a plain BMCore struct using `FArchive`. There is no
`USaveGame`, no `UPROPERTY`, no `USTRUCT`.** BMSim's `UBMSaveSubsystem` is a thin facade that
resolves the campaign, does the file touch, and forwards — the S3 `UBMJobSubsystem` shape, guarded by
the same scan.

**The two-piece split is mandated, not merely convenient.** `04` §2's BMCore row lists under "Must
NOT contain": *"Any UObject-derived gameplay type, any Actor, any rendering, **any file I/O**"* — while
the same table's BMSim row lists **"save"** under *Contains*. So the codec (pure, in-memory,
`TArray<uint8>`) is BMCore and the `FFileHelper` touch is BMSim. This is also exactly the oracle's
own shape: `SaveCodec` (pure `RefCounted`) + `SaveService` (autoload, does the file I/O).

Precedent already in the tree: `UBMCampaignSubsystem` holds its `FBMCampaignState` as *"a plain
member, not a UPROPERTY… why the state cannot be a USTRUCT"* (`BMCampaignSubsystem.h:48-51`).
**The plan contradicts code that already shipped, and that code's comment says why.**

Worse, the two documents **disagree with each other**: `04` §8's sketch uses separate mirror types
(`FBMFactionSave`, `FBMDistrictSave`), `05` §7's uses the live BMCore structs directly. Both are
uncompilable; they are not two readings of one design. `04` §8's stated *goal* — *"serialized through
`FArchive` (binary, float-exact — the requirement Godot met with `var_to_str`)"* — is met exactly by
D-S4-1. What is lost is only reflection-driven auto-serialization; what is **gained** is explicit
field-order control, which a hard-version-refusal contract wants anyway (see F-3).

⚠️ `04` §8 also prescribes `FCustomVersion` "to formalize what Godot did with `.get(key, default)`."
**Not adopted in S4.** `FCustomVersion` is a CoreUObject/`FArchive`-UObject-path mechanism for
engine-versioned reflected serialization; a hand-rolled codec gets additive tolerance more simply and
more testably from one explicit version int plus defaulted struct members — which is what
`Test_Save_AdditiveField` measures. Recorded as part of D-S4-1.

### F-2 — The version check is COERCIVE, not typed. A "validating" port refuses valid saves. `[MEASURED]`

`save_codec.gd:110` is `int(data.get("version", -1)) != SAVE_VERSION`. Driven against the oracle:

| input | oracle | why |
|---|---|---|
| `{}` | **refused** | default `-1` |
| `{"version": 1}` | **accepted** | — |
| `{"version": "1"}` | **ACCEPTED** | `int("1") == 1` — a *string* passes |
| `{"version": 1.0}` | **ACCEPTED** | `int(1.0) == 1` |
| `{"version": "abc"}` | **refused** | `int("abc") == 0` |

This is the **exact shape of the S3 id-parse trap**: Godot coerces silently and a port that
type-checks rejects input the oracle accepts. A binary `FArchive` format has no string-vs-int
ambiguity, so **the coercion is unreproducible and must be recorded as a bounded divergence, not
imitated.** What ports is the *refusal semantics*: wrong version → refuse whole load, state
untouched, no partial application.

### F-3 — `var_to_str` SORTS dictionary keys. The oracle's snapshot equality is order-insensitive by accident. `[MEASURED]`

`encode_state` builds keys in insertion order (`["version","meta","factions","districts",
"characters","jobs"]`), but `var_to_str` emits them **alphabetically** (`characters, districts,
factions, jobs, meta, version`). The roundtrip runner compares `var_to_str(...)` strings, so field
order cannot affect its verdict.

A binary archive has **no such forgiveness** — field order *is* the format. So:
- Oracle "byte-identical" means *value*-identical modulo key order.
- UE "byte-identical" means the archive bytes match, which is **strictly stronger**.
- ⚠️ A reordered `Serialize()` is a silent save-format break with **no test symptom** unless a
  committed fixture from the previous build is replayed. → `Test_Save_FixtureCompatibility`.

### F-4 — Floats: the oracle is float64-exact; the port is float32. `[MEASURED]`

`var_to_str` emits up to 17 significant digits and round-trips float64 **exactly** (`1/7` →
`0.14285714285714285`; `0.1+0.2` → `0.30000000000000004`, exact). The codec's own header says JSON
would *"truncate floats and break save→load→same-tick→same-state determinism."*

**24 saved float64 fields are `float` (binary32) in UE** — 7 district, 6 venue, 1 faction
(`Grudge`), 1 evidence (`Weight`), 9 job-outcome, 1 meta (`CentralPressure`).

This is **not** a precision problem for S4, and it is important to say why rather than widen types:
`FArchive` on a `float` is a **bit-exact 4-byte copy**. Save→load is exact *within the port*, which
is what the gate measures. The f64→f32 narrowing is an S1/S2 concern already settled by the
existing `1e-5` vector tolerance. **S4 asserts EXACT (`==`) float equality on its own round trip**,
not `1e-5` — a tolerance on a round trip is not a tolerance, it is a bug that hides truncation.

### F-5 — A load that DROPS a job still SUCCEEDS. "Byte-identical" and "honest" are different contracts. `[MEASURED]`

`save_service.gd:88-90` `continue`s past any job whose id neither `JobTemplates.by_id` nor
`JobGenerator.rebuild` can resolve, pushes a warning, and **returns `true`**. Measured: 3 jobs
saved, 1 restored.

So the loaded campaign is **legitimately not equal** to the saved snapshot. The gate's
"byte-identical" holds only when every job id still resolves. Two distinct assertions, and
conflating them produces either a false pass or a false fail:

- `Test_Save_RebuildContract` — all ids resolve → state equal.
- `Test_Save_MissingJobDefinition` / `StaleCaseReference` — an id does not resolve → load **succeeds**,
  that job is **absent**, every other job is **intact**, and state is deliberately **not** equal.

### F-6 — `JSON.stringify` TRUNCATES float64 to 15 digits. The fixture must emit decimal strings. `[MEASURED, found during Step 1]`

Found while inspecting the first extractor output — the fixture was **lying about the floats it
claimed to pin**:

| value | `JSON.stringify` | `var_to_str` |
|---|---|---|
| `0.1 + 0.2` | `0.3` ← **a different number** | `0.30000000000000004` |
| `1.0/3.0` | `0.333333333333333` (15) | `0.3333333333333333` (16) |
| `-1.0/7.0` | `-0.142857142857143` | `-0.14285714285714285` |

**Why this bites S4 and not S2/S3.** Those fixtures also use JSON numbers, but compare at `1e-5` —
looser than the truncation, so it never showed. **S4 compares floats with `==` (F-4)**, so a
truncated fixture **fails a CORRECT port.** This is the same failure class as S1's 64-bit avalanche
values silently rounding through a double, and it takes the same fix: **emit every float as a decimal
string** via `var_to_str`, read it back with a full-precision parser. Verified 20/20 exact on the
adversarial set, including through a JSON round trip as a string value.

Also worth knowing: GDScript's own `%s` and `print()` truncate to **14** digits. `var_to_str` is the
only writer in the engine that tells the truth about a float — *the S1 lesson restated: the printed
value is not evidence.*

The extractor now emits `"float_encoding": "decimal_string"` and the fixture audits clean at **0 raw
JSON floats.**

## 5. The load sequence — order is behavior

Transcribed from `save_service.gd:44-101`. Four things a port gets wrong by writing it naturally:

1. **Version first, before touching anything.** Refusal must leave state untouched — an in-place
   deserialize that validates late corrupts the campaign on a bad file. Deserialize into a
   **scratch** `FBMCampaignState`, then commit by move.
2. **Pause before writing state.** `save_service.gd:65` sets `Speed.PAUSED` *before* the assignments,
   *"so nothing settles against half-restored state."* → `Test_Save_LoadLeavesPaused`.
3. **Rebuild jobs `by_id` FIRST, then `Rebuild`, then skip.** Authored ids must not reach the
   generated parser. `ById` returning false for an unknown authored id is the honest answer (D-S3-4).
4. **`RestoreJobs` is a straight assignment** (`job_director.gd:94-96`) — array order preserved, no
   stage or deadline reset. The oracle re-emits `job_offered` for unresolved jobs; BMCore has no
   delegates, so that lands on the subsystem when the UI slice arrives.

⛔ **No pointers held across a load.** `07` §S4 prohibits it and `FBMCampaignState` makes it easy to
violate: `Districts` is a `TArray`, so every `FBMVenueState*` and `FBMDistrictState*` is invalidated
by the reallocation. Re-resolve by Id after the commit.

## 7. Mutation testing — NOT optional

S2 found 3 gaps and S3 found 4 **by mutation, not by the gate failing.** Two of S3's were in a guard
green since S1 that was *structurally unable to fail*. **First-run green is weak evidence in this
repo.** Every mutation below gets run; each must turn the suite red, and any that does not is a
**test gap to close before the gate is claimed.**

| # | Mutation | Expected catcher |
|---|---|---|
| 1 | `float` → `double` on one field, or a truncating cast in the archive | `FloatExactRoundTrip` |

| 3 | Validate the version *after* deserializing in place | `VersionRefusal` ("state untouched") |
| 4 | `!=` → `<` on the version compare | `VersionRefusal` |
| 5 | Try `Rebuild` before `ById` | `RebuildContract` |
| 6 | Return `false` from load when a job is skipped | `MissingJobDefinition` |
| 7 | On a stale `burycase`, rebuild a job with an empty case instead of failing | `StaleCaseReference` |
| 8 | Reset `TicksRemaining` to the deadline after rebuild (skip the overlay) | `RebuildContract` |
| 9 | Drop `bResolved`, infer "all nine zero" instead | `JobRebuildByteIdentical` — the `BMJobTypes.h:84` trap |
| 10 | Serialize `LastSettle` / `DistrictTickExposure` | `ReplayAfterLoad` |
| 11 | Skip the pause before restoring | `LoadLeavesPaused` |
| 12 | Use one segment count for all four rebuild templates | `RebuildContract` (§4) |
| 13 | Reimplement a format decision in `UBMSaveSubsystem` as a bare literal | `SubsystemIsAThinFacade` |

| 15 | Add an `FFileHelper` call to `BMSaveCodec.cpp` | `NoFileIoInBMCore` |

## 8. Steps

Each step ends with the full gate green (`Automation RunTests BM`, exit 0, editor build 0 warnings)
before the next begins. A red gate is diagnosed, never worked around.

1. **Extractor** — `tools/export_save_vectors.gd` in the oracle repo; run **twice**, require
   byte-identical output (the S1/S2/S3 rule). Commit the fixture.
2. **`BMSaveTypes.h` + `FBMSaveCodec`** — `FArchive` serialization of `FBMCampaignState`.
   `Test_Save_FloatExactRoundTrip` + `AdditiveField` + `VersionRefusal` + `CorruptFile`.
3. **`UBMSaveSubsystem`** — file I/O, the load sequence of §5, the rebuild loop.
   `RebuildContract` + `JobRebuildByteIdentical` + `MissingJobDefinition` + `StaleCaseReference` +
   `LoadLeavesPaused`.
4. **Determinism** — `ReplayAfterLoad` against the existing trajectory harness. Re-run
   `BM.Equivalence.TrajectoryMatchesOracle` **before and after** wiring, as S3 did, to prove the
   save layer perturbs nothing.
5. **Guards** — `NoUIStateInCampaign`, `SubsystemIsAThinFacade`, `FixtureCompatibility`. Commit
   `v1.bmsav`.
6. **Mutation pass** — all **15** (§7's table). Close every gap found. Record the table.
   ⚠️ If mutation 2 finds a gap, the fix is to **tighten the byte comparison, never to loosen the
   fixture.** Standing instruction from Cem, 2026-09-19.
7. **Gate** — full suite + editor build + Shipping package. Write `Docs/gates/S4.md`, update
   `NOW.md`, tag `s4-save`.
